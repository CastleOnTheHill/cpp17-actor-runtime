# Actor benchmark 工作记录

目标：在本机 WSL 中建立可复现 echo benchmark，与主流 actor 框架同机对比，
保存原始测量、采样/火焰图数据，给出有证据的瓶颈分析和优化建议。
只新增测量工具，不把未验证的运行库优化混入基线。

## 验收清单

- [x] 记录 CPU、内核、编译器、依赖版本、优化编译参数与测量口径。
- [x] echo 校验请求/回复内容与数量，报告 round trips/s 与 RTT 分位数。
- [x] 测量 worker 数、并发量、载荷大小变化，区分 event 与 fiber 等待。
- [x] 测量真实 Unix datagram 跨进程 echo，区分 C bridge 与传输成本。
- [x] CAF、SObjectizer 固定版本同机对照；不把网上数字当成实测。
- [x] 多轮测量、预热、明确计时区间；性能运行不启用 ASan/coverage/诊断日志。
- [x] 保存原始 profiler 数据、折叠调用栈和火焰图，并说明采样权限或工具限制。
- [x] 基于测量形成差距分析、可证伪假设及优化优先级；不虚构收益。
- [x] 验证 benchmark 自身的计数/超时/参数检查及现有运行库回归。

## 可扩展场景

基础：单客户端往返延迟、多客户端/多对 actor 吞吐、单热点 actor 竞争、
0/64/1024 字节 payload、1/2/4 worker、事件驱动与有栈等待、真实 IPC。
后续：广播 fan-out、Actor 创建/销毁、fiber 创建/回收、嵌套等待、阻塞池
满载和超时公平性、长时间内存增长。报告中区分已执行与仅设计的场景。

## 公平性约定

请求的一次完整应答计为 1 round trip（2 条 actor 消息），不混淆 req/s、
msg/s 和 MB/s。对照使用相同逻辑 payload、并发窗口、worker 数、
预热策略和编译优化；框架特有的批处理、内存所有权、调度模型另行解释。
延迟为闭环负载下的 RTT，不宣称代表开放环过载时的服务延迟。
采样运行与吞吐统计分开，避免 profiler 的扰动污染对比数据。

初轮按各框架速率校准约 1 s 的请求数，再固定该数重复三轮；补测才使用同拓扑相同请求预算重复五轮。

当前：53 配置 × 3 轮、12 补测 × 5 轮、6 次唤醒对照、8 组真实火焰图、11/11 CTest 已完成。
详细方法、实测、限制和优化顺序见 BENCHMARK_REPORT.md；209.5 MiB 原始证据已保存并通过131项文件哈希校验。
验收记录见 BENCHMARK_VALIDATION.md。运行库未修改；没有将低样本图、波动配置或诊断 pulse 作为稳定容量/优化收益。
