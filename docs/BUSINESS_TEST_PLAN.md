# 业务集成测试扩展方案（待确认公开接口边界）

## 基线与覆盖率口径

当前 dev 的现场报告：运行库行覆盖率 1015/1041 = 97.50%；原始 gcov
分支覆盖率 995/1657 = 60.05%，包含编译器生成的 C++ 异常边。
已有 10 个 CTest 目标；订单履约示例仅使用进程内模拟服务，真实 IPC
测试主要验证 C/POD echo 路由，不能代替跨进程业务流程的正确性证明。

建议将本次“80%+”按运行库行覆盖率解释，并保留既有 >=90% 门禁。
同时报告原始分支覆盖率，不宣称其已超过 80%，不排除错误分支来抬高数字。
若要求的是分支覆盖率 >=80%，需要确认该独立验收指标。

## 待确认的公开接口边界

1. ActorSystem::sendBytes / replyBytes 和 ActorAddress：真实进程间字节请求应答。
2. ar_client_request / ar_reply 等 C ABI：真实 C 模块与 Actor 系统交互。
3. registerActor / findActor / stopActor 与 RuntimeStats：动态实例与资源清理。
4. CoroutineContext 的 submitBlocking / blocking / await / cancel：任务、消息、
   子协程和计时器的组合等待，以及业务取消。

仅通过这些公开接口发起操作、检查结果，不访问私有队列/等待表，不模拟
运行库自身组件。动态加载仍指实例注册/注销，不在测试中偷换成 .so 热加载。

## 业务场景矩阵

| 边界 | 业务场景 | 可观察验收结果 |
| --- | --- | --- |
| IPC | 两个仓库进程都有 stock Actor，按进程名选择仓库 | 返回各仓库独立库存/报价，订单号和 POD 字段完整 |
| IPC | C 网关向订单 Actor 下单，订单跨进程查询库存和支付 | 成功订单返回明确终态，查询确认预留/扣减结果 |
| IPC | 库存不足 | 订单拒绝，不发起支付，不产生库存扣减 |
| IPC | 请求等待期间服务进程退出 | 请求在截止时间内结束，其他服务仍能响应 |
| IPC | 服务以原进程名和 Actor 名重新启动 | 新订单成功，旧订单的迟到结果不污染新订单 |
| C ABI | 多个 C 客户端并发下单 | 应答的订单号、关联和金额不串单 |
| C ABI | 同一 client 的并发调用 | 每次调用返回自己的应答，不出现重叠等待污染 |
| C ABI | 第一次调用超时，迟到应答与第二次调用交错 | 第二次调用只接收自己的响应 |
| C ABI | 错误响应类型、短输出缓冲区、空载荷 | 返回准确状态和所需长度，后续合法调用仍成功 |
| C ABI | C 请求挂起期间关闭宿主系统 | 调用返回 CLOSED，cleanup 和 handle 生命周期符合契约 |
| 生命周期 | 在订单等待库存/支付时停止订单 Actor | 已启动协程正常取消展开，停止完成后资源清理完成 |
| 生命周期 | 旧订单 Actor 正在退出时立即创建同名实例 | 新实例可接受请求，旧引用及旧回复无法投递到新实例 |
| 生命周期 | 外部发送与停止并发 | 已接受/拒绝的边界清晰，无崩溃、重复完成或遗留栈 |
| 生命周期 | 多轮会话创建、关闭和同名重建 | 每轮终态可观测，关闭后 liveFibers/liveStacks 为零 |
| 阻塞任务 | 旧 C 风格支付函数成功或抛异常 | 订单分别得到成功/失败，不终止调度 worker |
| 阻塞任务 | 支付函数未返回时订单超时 | 超时订单及时结束，同 worker 上健康订单仍可完成 |
| 阻塞任务 | 超时后再次等待任务 | 返回唯一任务结果，不把旧超时事件当成新的完成 |
| 阻塞任务 | 一个任务运行、一个排队，第三个提交 | 第三次明确拒绝；释放闸门后前两次正确完成 |
| 组合等待 | 库存/风控 All，支付/撤单/超时 Any | 输出独立定义的订单终态，取消必要子协程并完成清理 |
| 组合等待 | 通知失败但审计成功的 AllSettled | 保留各分支结果，订单收尾不因通知异常丢失 |

业务上的幂等、回滚等规则由测试业务 Actor 实现，不误称为运行库提供的
持久化或 exactly-once 投递能力。无库存/金额副作用通过业务查询接口验收。

## 实现与验证顺序

确认边界后逐个纵向切片推进：一个业务预期 → 实现业务测试程序 → 验证该
场景，再增加下一个场景。已有功能的回归测试不人为制造运行库缺陷；新增
业务行为先证明失败，再补充业务实现。发现运行库缺陷时先保留最小复现。

- 测试代码继续位于 dev，teaching 不混入业务实现。
- 真正独立的进程和 Unix datagram socket，不用同进程对象替代 IPC。
- 跨进程使用零初始化、固定宽度、无指针 C struct，并校验尺寸。
- 优先使用握手、promise 和可释放闸门控制交错，避免靠固定 sleep 猜顺序。
- 所有测试/子进程设置截止时间；只清理测试自己启动的进程。
- 阻塞函数超时不强杀线程：测试必须释放闸门，让函数退出并完成 join。
- 场景日志包含业务订单号、阶段、预期终态和实际终态，不输出敏感载荷。
- 运行 WSL 普通回归、ASan/UBSan/泄漏检测、独立覆盖率构建；重复运行关键
  并发场景，并记录实际测试数量和新的覆盖率，不复用旧报告作新增测试证据。
