暂停到底保留了什么？

方式本次函数返回？继续信息在哪里？谁让它继续？
普通 return是没有保存旧调用可恢复现场；仅返回结果不能恢复旧调用；再次调用是新执行
手写 Task::next是仍存活 Task 的 phase + 数据成员调用者再次调用 next，从入口选分支
ucontext yield暂停时 inner 未返回独立栈 + 保存的 context调度代码加载 context，继续旧执行

对象与生存期

代码：操作的定义。调用：一次执行。局部对象：属于这次执行的状态。返回结果：输出给调用者的数据，不等于可恢复现场。

退出相关作用域与字节立即被覆盖不是同一件事；原对象不再存活时不能靠残留字节使用它。RAII 探针用构造/析构事件观察这一界线。见第一章及生存期依据。

显式状态机

phase：下次做哪段。value：下次带什么业务数据。Step：本次调用向外报告的结果。Finished：不再执行业务副作用的终态。

这里的“持久状态”不必在堆上，只需所属对象跨越多次 next 仍存活。并未保存 next 的调用栈。见第二章。

有栈切换

Fiber：本课程对一条有栈协作执行流的称呼。Stack：独立栈的存储。Context：恢复现场的记录，不是整栈字节备份。Scheduler：选择下一条执行流的代码，不天然等于独立线程。

swapcontext(&当前现场的保存处, &将要进入的现场);
// scheduler → fiber：save scheduler, load fiber
// fiber → scheduler：save fiber, load scheduler

yield：主动让出；本章 inner 的局部作用域不结束。resume：让保存的执行继续。done：已经完成，拒绝恢复。uc_link：context 入口函数返回后的后继，不是“自动取消”。见第三章及API 依据。

后续术语预告，不作本章考核

Actor：串行访问自身状态的执行实体。CoroutineContext::await：框架级等待操作，包括登记、切换与恢复后的处理，远多于裸 yield。worker：运行调度循环的 OS 线程。owner：框架固定给 fiber 的 worker 归属；不要与 Actor 当前执行者混为一谈。

Any 结束不代表未胜出的 child 被取消；All 等到全部终态再汇总，并非 fail-fast；AllSettled 提供各 child 的终态。这些只在后续章逐个实验，不要求现在记忆。

最小诊断问法

现在执行在哪条栈？对象还活着吗？下一步信息在哪里？谁更新它？谁决定恢复？若输出与预测不同，从第一个不同事件回溯，不一次重学整套框架。
