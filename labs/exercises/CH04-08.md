# 第 4–8 章构建工单

每次只做一章。先写预测，再打开对应参考函数；在自己创建的副本中练习，不修改 `ch02_build_it.cpp`。本文件不是学习成绩单。

建议在仓库根目录的 WSL 中准备忽略目录（`labs/.gitignore` 的 `/build*/` 已覆盖）：

```bash
mkdir -p labs/build-practice/support
cp labs/support/fiber_lab.h labs/build-practice/support/
# 每次只复制本章，例如第四章；后续换成相应文件名
cp labs/ch04_ready_queue.cpp labs/build-practice/
g++ -std=c++17 -O0 -g -Wall -Wextra -Wpedantic -pthread \
    labs/build-practice/ch04_ready_queue.cpp -o labs/build-practice/ch04
./labs/build-practice/ch04 round-robin
```

`cp` 是你首次建立副本的命令；如果已开始练习，不要重复执行覆盖自己的改动。第 4–6 章副本使用副本里的 support/fiber_lab.h；第 7–8 章不需要该头文件。保留错误检查、入口捕获、context 地址稳定性、已完成状态保护，不通过触发未定义行为来练习。

## 第四章

核心函数：`Loop::step`。保留上下文切换前后的固定外壳，仅挖空 Ready 分支的排队动作；按状态表恢复。Done 分支和回收暂不改变。

- 先纸上构建：A 三段、B 一段、C 两段；每一步写 ready 和当前执行者。
- 再代码构建：调整各协程体和断言；应输出 A1/B1/C1/A2/C2/A3（完成者不再 yield）。
- 反例：只在副本里将入尾改为入头；预测再运行，然后恢复。
- 验收：Done 不再执行；空队列 step 为 false；解释为何 CPU 无限循环无法用队列策略修复。

## 第五章

核心函数：`sleepFor` 与 `advanceTo`。保留 suspend 的真实切换；自己实现“记录 deadline、标 Waiting、到时才 Ready”的部分。

- 构建：A 等 7，B 等 2，逐个推进 now=1/2/6/7；每次只运行已有 Ready。
- 断言：deadline 前不恢复；重复同一时刻不会二次入队；栈只在完成后回收。
- 边界：零时长约定为 yield；负时长必须拒绝；不能倒退模拟时间。异常应在 scheduler 侧检查完成记录，不能只看日志。
- 验收：不用 sleep_for 或忙等完成实验；说明 tick 与真实毫秒的差别。

## 第六章

核心函数：`collect`。保留“active_ 必须为空”的前置检查，自己填 finished 清单的消费、Done 检查和所有权释放。

- 构建：关闭自动回收，明确观察暂停/完成未回收/回收后三阶段。
- 变式：Completion 加一个值结果，释放栈后读取，不允许使用局部对象裸指针。
- 反例检查：fiber 内 collect 必须被拒绝；第二次 collect 必须为零；Done 不可再执行。
- 验收：在正常、抛异常、64 条任务三种情况下，解释对象数、栈数、记录数的差别。

## 第七章

核心函数：`CounterActor::handle`。先标出必须同属一个临界区的访问，再自己放置 RAII 锁；不要运行去锁后的真实多线程版本。

- 构建：一个 Actor，1/4 worker 各处理 2000 个任务；全部 join 后读取结果。
- 变式：两个 Actor 各有独立锁、各有自己的计数与任务配额。
- 失败：在修改业务状态前抛一次异常，验证后续任务仍能处理。解释异常解锁不等于事务回滚。
- 验收：给出安全领取任务仍会业务交错的模型；不能靠把 value 改成 atomic 绕过“Actor 多字段串行”的问题。

## 第八章

核心函数：`post` 的容量/关闭判断、`dispatchOne` 的类型与载荷检查。执行锁与邮箱锁的顺序保留。

- 构建：新增 Set 类型（编号 2），Set{10}→Add{2} 应得到 12。
- 类型变式：编号 2 携带 Add 对象，必须被消费但不修改业务值。
- 容量变式：容量 2，第三次发送拒绝；消费一次后再发成功。故意把 `>=` 改成 `>`，检查边界测试能发现问题，再修回。
- 验收：分别解释 Accepted、Consumed、Applied；close 后排空是本模型约定，不宣称真实框架完全相同。
